# Host Tool Analysis Pipeline  
- A high‑level overview of how the Climate‑Based Monitoring Device’s host‑side analysis pipeline operates.

## Purpose  
- The host tool processes raw sensor data collected by the embedded device and produces a complete analysis package including:

    - Basic statistics  
    - Trend detection  
    - Anomaly detection  
    - Visual plots  
    - A human‑readable summary  

- The pipeline is modular, testable, and designed for future expansion.

---

## Pipeline Overview  
- The pipeline consists of four major stages:

    1. **Sensor Data Ingestion**  
    2. **Data Analysis (Stats, Trends, Anomalies)**  
    3. **Plot Generation**  
    4. **Summary Output**

- Each stage is implemented as a separate module to keep the codebase clean and maintainable.

---

## 1. Sensor Data Ingestion  
The sensor reader module handles the conversion of raw CSV logs produced by the embedded device into a structured binary format (`output.bin`) for downstream analysis.

### **a. CSV Discovery**  
Locates the newest CSV file generated by the device, supporting both normal operation and test overrides via environment variables.

### **b. CSV Parsing**  
Reads header fields and data rows, validating that the file is present, non‑empty, and correctly formatted.

### **c. Value Extraction**  
Parses timestamps and sensor readings (temperature, humidity, pressure, air quality, CO₂, VOC) and converts timestamps into minutes since the first reading.

### **d. Binary Export**  
Packs each record as seven doubles and writes them sequentially to `output.bin`, producing a compact binary stream for the host analysis pipeline.

### Output  
A structured binary file containing normalized sensor readings, written to the project’s data directory for use by the analyzer and plotter modules.

---

## 2. Data Analysis  
- The analyzer module performs the core computational work. It is composed of three sub‑analyses:

### **a. Basic Statistics**  
- Computes min, max, mean, and other descriptive metrics for each sensor channel.

### **b. Trend Detection**  
- Identifies long‑term directional changes in the data (e.g., rising temperature, falling humidity).

### **c. Anomaly Detection**  
- Flags unusual or out‑of‑range readings using thresholding or deviation‑based logic.

### Output  
- A structured analysis file containing all computed metrics, written to the pipeline’s output directory.

---

## 3. Plot Generation  
- The plotter module visualizes the sensor data and produces a timestamped PNG file containing six aligned time‑series plots. 
- It uses portable path construction to ensure compatibility across operating systems and test environments.

### **a. CSV Loading**  
- The module locates the newest CSV file in the firmware output directory (or a test directory when running in test mode). 
- It loads all rows and extracts timestamps and sensor values for plotting.

### **b. Data Normalization**  
- Timestamps are converted into minutes since the first reading, creating a normalized time axis. 
- All sensor channels (temperature, humidity, pressure, air quality, CO₂, VOC) are parsed into floating‑point arrays.

### **c. Multi‑Channel Plot Rendering**  
A single figure is generated containing six stacked subplots, one for each sensor channel. Each subplot shares the same time axis, providing a synchronized view of sensor behavior over the recording period.

### **d. Timestamped PNG Export**  
- The plot is saved as a PNG file using a dynamically generated timestamp in the filename, such as: `plot_2026-08-01_17-34-52.png`. 
- The output directory is constructed portably using: `os.path.join(PROJECT_ROOT, "03_data", "output_data", "plots") `
- This ensures the plot is saved to: `<PROJECT_ROOT>/03_data/output_data/plots/`
- If running in test mode, the plot is generated but not displayed.

### Output  
- A timestamped PNG file containing six synchronized sensor plots, saved to the project’s portable output directory for inclusion in the host‑tool analysis pipeline.

---

## 4. Summary Output  
The summary module produces a comprehensive, human‑readable report that consolidates all results from the analysis pipeline. It transforms raw numerical output into an interpretable environmental assessment.

### **a. Summary Statistics**  
Displays min, max, and average values for each sensor channel, along with sparklines that visualize short‑term trends in a compact form.

### **b. Anomaly Detection Results**  
Reports whether any readings fall outside expected ranges.  
If no anomalies are detected, the summary explicitly states this.

### **c. Trend Detection Overview**  
Shows how each metric has changed over the full recording period, including direction (rising, falling, stable) and numerical deltas.

### **d. Environmental Interpretation**  
Provides readable insights based on sensor behavior, including:
- Weather and atmospheric stability  
- Air quality and pollution indicators  
- Comfort assessment (temperature, humidity)  
- Environmental stress signals  

These interpretations help users understand the meaning behind the data rather than just the numbers.

### **e. Pipeline Status and Artifacts**  
Includes:
- Confirmation that all pipeline stages completed successfully  
- The number of samples processed  
- The total time range covered  
- The path to the generated plot PNG file  

### Output  
A fully formatted analysis report containing statistics, sparklines, anomaly results, trend summaries, and environmental interpretation — allowing users to understand system behavior without inspecting raw data.

## Execution Flow  
The host tool processes data in a strictly ordered sequence, ensuring each stage produces the artifacts required by the next. The flow reflects the real behavior of the system as implemented in the sensor reader, analyzer, plot generator, and summary writer.

1. **Sensor Data Ingestion**  
   - The newest CSV file is located and parsed.  
   - Timestamps and sensor values are normalized and exported as a structured binary file (`output.bin`).  

2. **Data Analysis**  
   - The binary file is read and processed.  
   - Statistics, sparklines, anomalies, and trends are computed.  
   - A detailed environmental interpretation is generated.  

3. **Plot Generation**  
   - Sensor channels are plotted as synchronized time‑series graphs.  
   - A timestamped PNG file (e.g., `plot_2026-08-01_17-34-52.png`) is saved to the portable output directory:  
     ```
     <PROJECT_ROOT>/03_data/output_data/plots/
     ```  

4. **Summary Output**  
   - All results are consolidated into a human‑readable report.  
   - The summary includes statistics, anomalies, trends, interpretations, and paths to generated artifacts.  
   - The pipeline confirms successful completion.

This ordered flow ensures that raw device data is transformed into a complete, interpretable environmental analysis package.
